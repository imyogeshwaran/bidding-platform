# COMPLETE ONLINE AUCTION PLATFORM
## Full-Stack Frontend + Backend Development Prompt

Build a complete, professional, production-quality **Online Auction Platform** consisting of a React frontend and Node.js/Express backend.

This is a **Software Metrics academic project**, so the application must not only provide auction functionality but also provide measurable software/system metrics and project-specific metrics.

============================================================
IMPORTANT SCOPE RULE
============================================================

Build:

1. Complete Frontend
2. Complete Backend
3. REST APIs
4. Real-time bidding using Socket.IO
5. Authentication and role-based authorization
6. Auction management
7. Bid management
8. Notifications
9. Watchlist
10. Transaction workflow
11. Software Metrics Engine
12. Bidding Engagement Score (BES)
13. Auction Fairness Score (AFS)
14. Performance monitoring
15. Admin metrics dashboard
16. Testing-ready architecture
17. SonarQube-ready code structure
18. JMeter-ready performance APIs

DO NOT:

- Create the actual database.
- Configure MongoDB Atlas.
- Create MongoDB collections.
- Create database deployment.
- Hardcode database credentials.
- Hardcode API credentials.
- Implement a real payment gateway.

Instead, create a clean **repository/data-access abstraction layer** so a database can be connected later without changing the frontend or business logic.

11. REAL-TIME BIDDING
============================================================

Use Socket.IO.

When a valid bid occurs:

1. Backend validates it.
2. Backend records it.
3. Current price updates.
4. Bid count updates.
5. Bid history updates.
6. Socket event is emitted.
7. All connected auction users receive the update.

No page refresh should be required.

Handle:

- Connect
- Disconnect
- Reconnect
- Connection errors
- Auction rooms

Events:

auction:bid
auction:closed
auction:updated
notification:new

Successful Transactions / Won Auctions × 100

11. User Retention Rate

Each metric should expose:

- Current value

============================================================

Implement the project-specific:

Bidding Engagement Score (BES)

BES = 0.4U + 0.4B + 0.2T

Where:

U = normalized unique bidder participation
B = normalized bid activity
T = normalized time-based participation

Score range:

0–100

Show:

- Overall score
- Unique bidder score
- Bid activity score
- Time participation score
- BES trend
- Auction comparison

BES = 72/100

40. MOST IMPORTANT REQUIREMENT
============================================================

The entire application must remain faithful to the **Online Auction Platform Software Metrics project specification**.

Do not replace the project's metrics with unrelated analytics.

The following must remain central to the system:

- Bid Success Rate
- Bid Rejection Rate
- Average Number of Bids per Auction
- Auction Completion Rate
- Average Auction Participation
- Average Bid Processing Time
- Average Auction Duration
- User Activity Rate
- System Response Time
- Transaction Completion Rate
- User Retention Rate
- Price Increase Percentage
- Bidding Engagement Score (BES)
- Auction Fairness Score (AFS)

The application should collect the underlying data required to calculate these metrics automatically.

The software metrics should not be merely static numbers displayed on the UI.

They must be derived from the application's actual auction/bidding activity through the backend metrics engine.

The frontend must visualize those calculated values clearly.

The final result should be a complete, clean, professional **Online Auction Platform + Software Metrics Demonstration System**.

Do not add unrelated functionality that changes the project's scope.
